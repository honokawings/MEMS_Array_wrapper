# COM3 时钟诊断与 PLL 参数修正

> 历史专项诊断：CLK2 独立时钟诊断，PHY 保持复位，不提供完整网络链路。当前八路 CLK / 1.8 V 完整系统使用 UART SYS3，入口见[联调指南](../../../doc/system_uart_debug.md)与[当前发布报告](../../../doc/reports/clk8_18v_update.md)。下文位流及操作仅适用于该专项工具。

本版通过 UART 反馈全部信息，不再通过 LED/按键组合读状态。观察器、UART 和软件复位控制都运行于独立的 27 MHz 域；以太网 PLL 不锁定、公共复位未释放时仍可收发日志和命令。

**2026-09-18 构建发布及 COM3 实板测试均 PASS。** UART 基础测试 777 项、厂商 PLL 模型集成测试 2948 项，共 **3725 项检查通过**，集成测试解码 18 个完整串口记录；10 个封装引脚及快/慢角时序检查通过。`.sbit` SHA-256：`6c61a0b89e97c5e60ac3753bdda67027f4f251df039418edf3969768c73b5930`。用户确认下载后，COM3 连续采集 30 秒，收到 125 条完整记录，软件复位、自检模式开关、清除/查询命令及音频心跳七项检查全部通过。

## 本次修正的依据

上版板上反馈为默认页 `1100`、频率页 `1110`、复位页松 KEY0=`0000`。这表示输入 125 MHz、96 MHz 和 122.88 MHz 的相对频率合格，但以太网 PLL 未锁定，公共及局部复位一直未释放。分频器复位受该 LOCK 控制，因此分频后 125 MHz 不合格不能单独证明 PLL 的原始 250 MHz 输出完全停振。旧历史页只记录曾正常后的丢失，`0000` 不能排除启动失败。

已找到旧配置违反的一项厂商组合约束：PDS 2022.2-SP6.4 的 `ipm2l_pll/ui.tcl` 中 `pllCheck_adv` 要求 GPLL 在 `LOW/OPTIMIZED` 带宽下的 PFD 为 10～40 MHz；高于 40 MHz 须使用 HIGH。旧以太网参数 `I=1,M=4,F=2,O=4,BANDWIDTH=OPTIMIZED` 的 PFD=125 MHz，不满足这个约束。

本版改为 **I=4、M=16、F=2、O=4、OPTIMIZED**：PFD=31.25 MHz，VCO=1000 MHz，输出仍为 250 MHz，专用 /2 后仍为 125 MHz。保持低/中带宽配置，未以强行放开 LOCK 代替修正。脚本直接运行安装目录中的厂商校验函数，确认旧配置被拒绝、修正后三个 PLL 都被接受；行为模型与静态时序通过本身不能替代此模拟参数检查。

原系统 RTL、原位流和上版 LED 诊断均保留。该修正已在独立诊断中实板验证，完整系统网络故障尚未验证修复。

## 文件与连接

- JTAG 位流：`../../build/CLOCK_UART_PFD31/generate_bitstream/uart_clock_diag.sbit`。
- UART：**COM3，115200，8 数据位、无校验、1 停止位，无流控**。
- 板载 CP210x：FPGA 接收 `B24`、发送 `C24`，LVCMOS33；依据 MINI 硬件手册第 30 页。
- 分频系数 234，对应约 115384.6 baud，相对 115200 的偏差约 +0.16%。
- 每约 250 ms 输出一行；启动及接收命令后也会输出。每行在发送前一次性保存所有字段，发送途中不会混入另一时刻的状态。
- 命令触发的记录额外等待 16 个参考周期，让命令计数及复位状态的同步器更新；模式切换仍需原控制器约 20 ms 消抖，应以随后 `ctrl` 的变化确认完成。
- 四路麦克风时钟固定低，PHY 保持复位，因此没有网口链路和 UDP 属于预期。

## 上位机使用

下载新位流后，在工程根目录运行：

```powershell
.\fpga\diagnostics\uart_clock\host\capture.ps1 -Port COM3 -Seconds 30 -SelfTest
```

脚本识别到本版 `CLK2` 记录后，自动依次发送复位、进入自检、退出自检、清除历史、状态查询；验证复位确实拉低并释放、原音频心跳翻转、原控制器模式可切换及串口收发情况。不会在没有识别到本版协议前盲发命令。脚本退出时释放串口。

仅接收或单独下发命令：

```powershell
.\fpga\diagnostics\uart_clock\host\capture.ps1 -Port COM3 -Seconds 15
.\fpga\diagnostics\uart_clock\host\capture.ps1 -Port COM3 -Seconds 15 -Command r
```

COM3 同时只能由一个程序占用；使用采集脚本时关闭其他串口助手。脚本无需 Python/pyserial，支持 Windows PowerShell 5.1。日志默认保存到 `log/clock_uart/capture_时间/`：`raw.log` 原始字符、`records.json` 数值解析、`summary.json` 自动检查结果。`NO_DIAGNOSTIC_RECORDS` 表示未收到本版有效记录，不能判断时钟正常或异常。

也可用串口助手观察，并发送单个小写 ASCII 字符，无需回车：

| 命令 | 动作 |
|---|---|
| `s` 或 `h` | 立即申请一条状态记录 |
| `r` | 将三个 PLL/系统复位保持约 20 ms，然后重启；UART 和观察器计时继续运行 |
| `c` | 清除历史故障，当前异常 `now` 仍保留 |
| `t` | 模拟一次 100 ms 的原自检按键按下；模式改变需经过音频域消抖，接收回执可能先于模式变化 |

`t` 两次之间建议至少 0.2 秒。原控制器的本地/网络自检输入未接入，本版模式开启约 10 秒后会显示等待超时；自动测试会在此之前退出模式。

## 日志含义

格式示例（仅示例，不是实板采集结果）：

```text
CLK2 pfd=31.25 seq=0000000A ms=000003E8 lock=111 rst=111 freq=1111 delta=04C5,03AA,04B0,04C5 seen=F fault=0 now=0 ctrl=01 reset=0 cmd=73 cmds=0001 rxerr=0000
```

除 `pfd` 的十进制 MHz 常量、三组二进制状态和 `reset` 外，数值字段使用十六进制；上位机脚本会自动转换。

| 字段 | 含义与正常值 |
|---|---|
| `seq` / `ms` | 帧号 / 观察域启动毫秒数；`r` 命令不会清零 |
| `lock` | 从左到右：96、音频 122.88、以太网 PLL；正常 `111` |
| `rst` | 从左到右：公共、音频、以太网复位已释放；正常 `111` |
| `freq` | 从左到右：原始 125、96、音频 122.88、分频后 125 MHz；正常 `1111` |
| `delta` | 四路时钟 /1024 后在 10 ms 内的计数差；乘 0.1024 即 MHz 的相对估计 |
| `seen` | 已启用历史检查的位掩码；正常稳定后 `F` |
| `fault` | 曾正常后发生异常的历史位掩码；清除后正常为 `0` |
| `now` | 当前异常位掩码；即使从未成功启动也会显示，正常为 `0` |
| `ctrl` | 原控制器输出：bit0 音频心跳、bit1 自检模式、bit4 自检等待超时；复位未释放时输出 `00` |
| `reset` | 软件 PLL 复位正在保持，为 `1`；正常运行为 `0` |
| `cmd` / `cmds` | 最近识别的命令 ASCII 码 / 累计命令数；仅表示收到命令，不表示该动作已完成 |
| `rxerr` | FPGA UART 接收停止位错误计数；正常 `0000` |

`seen/fault/now` 位定义：bit0=公共/局部复位未释放，bit1=96 MHz PLL/频率，bit2=音频 PLL/频率，bit3=以太网 PLL/频率。例如旧板上症状对应 `lock=110 rst=000 freq=1110 now=9`，即便 `fault=0` 也清楚表明当前未正常运行。原始 125 MHz 输入独立查看 `freq` 第一个字符和 `delta` 第一个值。

刚下载以及 `r` 复位期间 `now` 非零、频率暂未合格是预期；稳定后应持续 `lock=111 rst=111 freq=1111 now=0`。频率检查以板上 27 MHz 为基准，不能测量绝对晶振误差、抖动或占空比。

## 构建和验证

```powershell
python fpga/diagnostics/uart_clock/build.py --sim-only
python fpga/diagnostics/uart_clock/build.py
.\fpga\diagnostics\uart_clock\host\test_parse.ps1
```

验证包含 UART 全部 256 个字节的收发、约 ±3% 波特率偏差、毛刺/停止位错误与恢复，及实际厂商 PLL 模型下的完整日志解码、命令控制、复位恢复、以太网失锁注入和历史清除。原语的模拟参数检查单独运行；布局布线后核对 10 个引脚、六个时钟和跨域约束，再导出位流。

调试过程包含一次编译命名修正、三次失败的集成仿真及一次主动中止的同步时序复查，最终完整回归通过。修正了 PLL 尚未运行时控制器状态不确定、换行编码，以及命令回执早于同步状态更新的问题；命令收到和消抖动作完成分别验证。

PDS 对 27 MHz 与 122.88 MHz 的共同周期仍有一项超过 1000 周期展开限额的提示。这里采用跨域同步并分别约束两个方向的物理布线延时 7.5 ns，报告逐项检查为通过；未放宽这些物理约束。五个固定低输出没有 IO 延时，UART 输入/输出的零参考延时提示也均记录于发布审计。

证据位于 `log/clock_uart/` 和 `fpga/build/CLOCK_UART_PFD31/release.json`。`release.json` 保留构建时尚未上板的原始快照，实板结果单独记录在 `log/clock_uart/board_verification_20260918.json`，并关联发布文件与日志哈希。
