# PG2L200H 时钟与复位诊断

> 历史专项诊断：使用按键/LED 页表的时钟复位诊断。当前八路 CLK / 1.8 V 完整系统使用 UART SYS3，入口见[联调指南](../../../doc/system_uart_debug.md)与[当前发布报告](../../../doc/reports/clk8_18v_update.md)。下文位流及操作仅适用于该专项工具。

五键、五灯的直接映射和时钟扫描诊断，已由用户在板上确认全部对应。本诊断继续检查参考时钟、三级 PLL、系统复位和原系统的按键控制器。

**2026-09-18 实板更新：** 用户反馈默认页 `1100`、频率页 `1110`、复位页松 KEY0=`0000`；以太网 PLL 未锁定，系统复位未释放。发现旧以太网 PLL 的 PFD=125 MHz 与 OPTIMIZED 带宽组合不符合厂商 IP 检查限制。后续按用户要求改用 [UART 诊断方案](../uart_clock/README.md)，不再以 LED/按键组合反馈。原始观测记录见 `log/clock_reset_diag/board_observation_20260918.json`。

2026-09-17 已生成位流：厂商模型 25 项、故障注入 44 项，共 **69 项仿真检查通过**；18 个封装引脚核对通过，快/慢角时序均为 `All Constraints Met`，构建发布状态 PASS。`.sbit` SHA-256 为 `56106521b352834dc3b8cad5ad1b8f521108f55a930712d9ba7bae7ea80dd1f1`。该构建的后续实板失败结果见上方更新，不能把构建 PASS 等同于硬件 PASS。

## 位流与使用范围

- JTAG 文件：`../../build/CLOCK_RESET_DIAG/generate_bitstream/clock_reset_diag.sbit`。
- 器件：PG2L200H，PDS 型号 `PG2L200H-6-FBB676`。
- 所有 LED 高电平亮，按键低电平有效；引脚沿用已实测的 IO 诊断。
- 27 MHz 观察域独立运行，KEY0 和 PLL 失锁都不会复位它。全局配置初始化仍会清零观察器。
- 复用正式设计的 PLL 参数、PLL 级联复位、`reset_release` 和 `board_selftest_control`。额外添加参考时钟缓冲及观察逻辑；布局与完整系统不同。
- 四路麦克风时钟固定低，PHY 复位保持低。本诊断下载后网口断链/没有 UDP 是预期行为，本次不测试网络收发。

## LED 页表

以下状态均按板上丝印 LED0 → LED4 排列。按住按键显示对应页面，松开返回默认页。

| 操作 | LED0 | LED1 | LED2 | LED3 | LED4 |
|---|---|---|---|---|---|
| 不按键 | 27 MHz 心跳 | 96 MHz PLL LOCK | 122.88 MHz PLL LOCK | 以太网 PLL LOCK | 公共复位已释放 |
| 按住 KEY1 | 27 MHz 心跳 | 输入 125 MHz 频率合格 | 96 MHz 频率合格 | 122.88 MHz 频率合格 | 分频后 125 MHz 频率合格 |
| 按住 KEY2 | 27 MHz 心跳 | KEY0 正在按下 | 公共复位已释放 | 音频域复位已释放 | 以太网域复位已释放 |
| 按住 KEY3 | 原音频心跳 | 原控制器自检模式 | 固定灭 | 固定灭 | 原控制器自检超时 |
| 按住 KEY4 | 27 MHz 心跳 | 曾发生非预期复位 | 曾发生 96 MHz 异常 | 曾发生音频时钟异常 | 曾发生以太网时钟异常 |
| 同时按 KEY3、KEY4 | 27 MHz 心跳 | 灭 | 灭 | 灭 | 灭 |

两种心跳均为每 **0.5 秒翻转一次**，亮灭完整周期约 1 秒。最后一行同时清除历史故障。多键优先级：清除组合键 > KEY4 > KEY3 > KEY2 > KEY1。

KEY0 仍是实际 PLL/系统复位。KEY1 同时接到原控制器：稳定按下超过约 20 ms 会切换一次自检模式，长按不重复切换。所以查看过 KEY1 频率页后，KEY3 页的模式灯可能已经改变。

KEY3 页未接入网络和本地自检结果，因此 LED2/3 固定灭；进入自检模式约 10 秒后 LED4 亮是控制器预期的等待超时，不能据此判断时钟故障。退出自检模式后该灯熄灭。

## 板上验证步骤

1. 通过 JTAG 下载上述 `.sbit`，以工具提示下载成功为计时起点。先不按键观察 3 秒：LED0 应开始约 0.5 秒一次翻转，LED1～4 应稳定亮。记录第一次心跳和各 LOCK 灯出现的时间，尤其是否仍有十几秒等待。
2. 按住 KEY1 约 1 秒：LED1～4 应全亮。拍照或按四位字符串记录，顺序为 LED1、2、3、4。
3. 按住 KEY2：预期 LED1 灭，LED2～4 亮。在保持 KEY2 的同时按住 KEY0 1 秒：LED1 亮、LED2～4 灭，LED0 应继续闪烁。松开 KEY0、仍保持 KEY2：LED1 灭、LED2～4 恢复亮。记录恢复耗时。
4. 松开所有键，再单独按下 KEY0 1 秒并松开，等待 1 秒。按住 KEY3：LED0 应为音频心跳，LED1 应灭。保持 KEY3 并按 KEY1 超过 0.1 秒：LED1 应亮；松开 KEY1 超过 0.1 秒后再次按下，LED1 应灭。观察期间 LED0 应持续闪烁。
5. 同时按 KEY3+KEY4 超过 0.1 秒，松开后等待 30 秒，不按 KEY0。按住 KEY4：LED1～4 应全灭。如果有灯亮，先记录，再清除；持续故障不会因清除而变成“正常”，实时页仍会显示异常。
6. 如果前面全部通过，可重新下载同一个诊断文件再重复步骤 1；若延迟只在下载阶段，计时起点必须是下载成功提示，而不是点击下载按钮。

建议反馈格式：

```text
下载成功→LED0首次翻转：___秒；之后每___秒翻转
默认页 LED1/2/3/4：____（1=亮，0=灭）
KEY1页 LED1/2/3/4：____
KEY2页：松KEY0=____；按KEY0=____；LED0是否继续闪：___
松KEY0后恢复：___秒
KEY3页：LED0是否闪___；KEY1是否每次切换LED1___
清除后等待30秒，KEY4页 LED1/2/3/4：____
```

## 如何根据结果继续排查

| 现象 | 结论与下一步 |
|---|---|
| 27 MHz 心跳不闪 | 先确认 JTAG 文件、配置成功状态、D18 时钟及新增全局缓冲路径。已有扫描诊断通过，不能直接归因于按键/LED 坏了。 |
| 默认页 LED1 灭 | 检查 27→96 MHz 的 PLL 锁定链。 |
| LED1 亮、LED2 灭 | 检查 96→122.88 MHz 的级联 PLL 和 `release_audio`。 |
| 默认页 LED3 灭 | 先查看 KEY1 页 LED1：输入 125 MHz 是否存在且频率正确，再检查以太网 PLL。 |
| LOCK 亮、对应频率灯灭 | 检查实际时钟输出、全局缓冲或分频器，不能只以 LOCK 判断时钟正常。 |
| KEY2 公共复位已释放、某局部复位未释放 | 对应时钟没有到达复位同步器，或该释放链异常。结合频率页定位。 |
| KEY2 的 KEY0 状态正确，但复位不改变 | 检查 KEY0→PLL/公共复位路径或实际加载的版本。 |
| KEY3 的音频心跳与按键切换均正常 | 本隔离设计的时钟/复位/控制器链路通过；下一版应增加 PHY 复位、MDC/MDIO 和链路状态观察。 |
| 隔离诊断正常，完整设计仍异常 | 继续比较完整设计的综合优化、布局、全局时钟资源、复位负载及真实 LED 语义。隔离通过不等于完整系统通过。 |

## 频率与历史检测的边界

- 每个源时钟先除以 1024，使用注册的 16 位 Gray 计数值跨域到 27 MHz。
- 10 ms 一次采样，误差阈值为目标计数的 ±2%，额外容许 2 个分频计数以覆盖量化与跨域端点差异。连续两次有效差分才点亮；全新启动需先建立基线，最早约 30 ms。
- 比较基准是板上 27 MHz，不能替代示波器对绝对频率、占空比、抖动、信号完整性的测量。
- 历史检测在对应项目曾正常后才启用。KEY0 按下会暂停并重新启用检测，避免把人工复位记成故障；已有历史不会因 KEY0 清除。
- KEY0 还会清除三路 PLL 输出的旧频率资格，松开后重新建立基线并连续两次合格；输入 125 MHz 检测保持运行，源域计数器不受 KEY0 复位。
- KEY4 的 LED2～4 包含对应 PLL 的锁定丢失或输出频率不合格。原始 125 MHz 输入只在频率页实时显示，没有单独历史灯。
- 状态经过同步采样；极短的亚周期 LOCK 脉冲以及被窗口平均掩盖的极短停钟不保证捕获。持续异常会被检测。

## 复现与证据

```powershell
python fpga/diagnostics/clock_reset/build.py --sim-only
python fpga/diagnostics/clock_reset/build.py
```

脚本先从正式时钟源文件确定性生成带观察端口的副本，再运行 ModelSim。仿真含厂商 PLL 模型和独立故障注入测试；后者覆盖停止四路时钟、错误频率、LOCK 丢失、非预期复位、人工复位屏蔽、历史清除和 Gray 计数回绕。

功能仿真经两轮收敛：首轮发现短按 KEY0 后旧频率资格导致历史误报，修复为重新建立频率资格，第二轮全部通过。首次编译的一处测试平台声明语法也已修正。后续只调整发布检查脚本时，使用输入/日志 SHA-256 完整核对复用上述仿真结果；未以跳过检查代替验证。

随后在独立目录执行综合、布局布线和快/慢角时序分析，核对全部 18 个封装引脚与 IO 电压标准、无时钟节点/组合环路/锁存器等检查。通过门禁后才在单独进程生成位流。原麦克风工程源文件和已交付位流不在修改范围内。

PDS 的 `unexpandable_clocks` 提示有一项已单独审核：122.88/27 = 1024/225，共同周期需要 1024 个音频时钟周期，超过其 1000 周期搜索限额。音频→观察域按注册 Gray 码/状态同步器处理，不依赖固定相位；所有四路观察跨域均保留 7.5 ns 物理布线约束并核对快/慢角结果。该提示没有通过放宽物理时序约束消除。五个固定低输出未加 IO 延时、按键/LED 的零参考延时提示也分别记录在发布审计中。
