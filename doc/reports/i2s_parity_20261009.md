# I2S 与奇偶补偿第一版发布、实板验证记录

记录日期：2026-10-09。本报告只对应第一版构建 **`MEMS_Array_i2s_parity_20261009`**。其工程联调发布和 JTAG SRAM 下载通过，实板 PHY/MDIO → ARP → UDP/BIST 数值链路通过；**UART 数字通道选择实板失败，完整目标尚未完成。** 修复候选计划使用 `MEMS_Array_i2s_parity_uartfix_20261009`，本报告不授予它发布、下载或实板 PASS。

## UART 数字通道配置故障

第一版独立音频自测报告为 **FAIL**，失败描述是 `Desired I2S configuration did not persist.`；脚本完成恢复控制，组增益目标恢复 unity。原始结果见[自测摘要](../../log/i2s_parity/board_audio_new_20261009/summary.json)和[原始串口](../../log/i2s_parity/board_audio_new_20261009/raw.log)。

随后[命令探针日志](../../log/i2s_parity/probe_audio_commands_20261009.log)进一步区分了命令类别：

| 命令 | 第一版实板观察 |
|---|---|
| `@I2S=1`、`@I2S=127` | 新鲜回应的期望/实际通道均为 0；稳定字段仍为 `0x80`（启用、通道 0） |
| `@I2S=128` | 未产生应有范围错误，仍显示启用通道 0 |
| `@I2S=OFF` | 关闭工作；再输入数字命令可启用，但仍选择 0 |
| `@GAIN=200000,300000` | 后续新鲜非 pending 查询显示实际增益 0.5 / 0.75 |
| `@GAIN=800000,400000` | 非法范围被拒绝，错误码 2 |
| `@I2S=strch` | 非数字格式被拒绝，错误码 1 |

[第一版 compile 日志](../../fpga/build/MEMS_Array_i2s_parity_20261009/compile/run.log)的 3057～3063 行明确记录：`desired_channel[6:0]` 七个寄存器均被移除为常量 0。这与数字命令始终选通道 0 的硬件行为一致。现已定位到原十进制解析写法在 PDS 编译后与 RTL 仿真行为不一致；原 RTL/板级测试通过没有覆盖这项厂商编译功能差异。

修正方向是固定字节位置、显式位宽的十进制解析，并用实际 PDS compile/synthesize/dev_map 导出的 UART 门级网表运行同类探针。厂商门级验证和完整第 17 层回归目前正在准备，修复候选尚未由本报告签核。SYS3 保持原 34 字、312 字节，音频仍用独立 I2S1/GAIN1；修复不应更改协议字段来规避原错误。

上述增益寄存器查询证明控制已应用，不证明真实麦克风 R/L 幅度配平。内部 `serial_errors=0` 也只验证所选 PCM 的内部串行格式；由于数字通道选择失效，它不能证明 128 路均已在第一版实板选通过，更不能替代 PCM5102 模拟输出验收。

## 真实输入的奇偶零增益检查

第一版退出 BIST 后，分别将偶组/奇组增益设为零，另一组保持 unity。每次先等待新鲜、非 pending 的 GAIN1 回帧确认实际增益与请求一致，再捕获真实麦克风 PCM。控制证据为[偶组应用](../../log/i2s_parity/gain_apply_even_first_20261009.json)、[奇组应用](../../log/i2s_parity/gain_apply_odd_first_20261009.json)；结束后的[恢复记录](../../log/i2s_parity/gain_restore_unity_first_20261009.json)确认实际两组均为 `400000`。

| 设置 | 捕获总帧 | 去除 96 帧稳定段后的核验帧 | 所选归零通道 | 非零违规样本 | 另一组非零通道 |
|---|---:|---:|---:|---:|---:|
| 偶组 0、奇组 1 | 144,291 | 144,195 | 64 | 0 | 64 |
| 偶组 1、奇组 0 | 143,373 | 143,277 | 64 | 0 | 64 |

两次结果分别见[偶组核验](../../log/i2s_parity/gain_zero_even_first_confirmed_20261009.gain_zero_even.json)和[奇组核验](../../log/i2s_parity/gain_zero_odd_first_confirmed_20261009.gain_zero_odd.json)，均为 `PASS_WITH_KNOWN_ISSUES`、`gain_zero_functional_pass=true`，而 `physical_amplitude_calibrated=false`、`dac_analog_verified=false`。两次已观察范围内均无缺包、重复、乱序、主机队列丢弃或非法负载，未出现队列溢出、调度错误、打包错误或自测标志。

全局历史 clip 标志在两次所有捕获帧中仍为 1，未被忽略或清除。它是粘滞状态，不能解释为每帧每通道均发生数值饱和；实际逐通道统计单独保留 rail 异常。偶组归零时，通道 2 归零、未静音的通道 3 仍恒为 `−8388608`；奇组归零时情况相反，通道 3 归零、通道 2 仍恒为 `−8388608`。这证明组增益零乘法对全部所选通道生效，也再次保留了 DATA1 双槽异常，不能宣称输入路径或声学配平已修复。
