## 设计与处理延迟

每级FIR从16条并行乘加流水改为8条，轮流处理128通道的16组数据。系数、完整部分乘积/累加、舍入饱和、历史RAM写暂存和有效提交规则不变。通道编号、帧号和采样时间轴保持不变。

| 参数 | 前一seed3基线 | FIR8 |
|---|---:|---:|
| 每级lane / 组数 | 16 / 8 | 8 / 16 |
| FIR1输入至valid | 546 clk | 1090 clk |
| FIR2输入至valid | 1058 clk | 2114 clk |
| 两级输出任务周期 | 1280 / 2560 clk | 1280 / 2560 clk |
| FIR历史逻辑容量 | 192 KiB | 192 KiB |

延迟公式为`G+2+G×(T+4)`。两级共增加1600个122.88MHz音频时钟，即**13.02µs共同处理延迟**；128路相对时间、48kHz采样率和抽取相位不变。1090/2114拍仍小于1280/2560拍任务间隔。奇偶/DC补偿仍为128通道131拍。

## 本次工程采集方式

本次使用日志内的[spool采集工具](../../log/i2s_parity/receive_pcm_spool_20261011.py)：实时仅接收并保存带时间戳的原始UDP，关闭接收后再交给原CaptureWriter离线解析。**原`lib/host/receive_pcm.py`及验收器未改**。原始`.udp_spool.bin`、`.pcm24le`、`.frames.jsonl`和`.summary.json`均保留，并由实际执行记录绑定哈希。

确认真实模式、unity、DC审核结束后，在工程根目录使用新的输出前缀，例如：

```powershell
python log/i2s_parity/receive_pcm_spool_20261011.py --bind 192.168.10.1 --seconds 3 --output log/capture/fir8_unity_run02
```

该工具不打开COM、不改变FPGA配置；UDP 5000必须由此接收器独占。输出前缀已有文件会拒绝覆盖，磁盘须容纳原始UDP、PCM和索引。`--seconds`只计实时接收，离线转换另耗时间。本次F的[实际执行记录](../../log/i2s_parity/fir8_auto_unity_spool_20261011/execution_F.json)绑定3秒接收命令和原件；A–E各阶段按顺序独占COM3，C/D阶段内UART与UDP并行，使用专属新tag，不复用已有证据目录。

## 物理与声学边界
